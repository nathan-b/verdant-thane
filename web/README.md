# Verdant Thane - Web Deployment

This directory contains the files needed to run Verdant Thane in a web browser using WebAssembly.

## Files

- **index.html** - Main HTML page with WASM loader
- **wasm_exec.js** - Go WebAssembly runtime (from Go SDK)
- **verdant-thane.wasm** - Game binary (generated by build)

## Building for Web

Use the provided build script to compile the WASM binary:

```bash
# From project root
./scripts/build-wasm.sh
```

This will:
1. Compile the game to `web/verdant-thane.wasm`
2. Copy the latest `wasm_exec.js` from your Go installation
3. Verify all required files are present

## Local Testing

To test the game locally, you need to serve the `web/` directory with an HTTP server:

```bash
# Option 1: Python 3
python3 -m http.server --directory web 8080

# Option 2: Python 2
cd web && python -m SimpleHTTPServer 8080

# Option 3: Go
go install github.com/shurcooL/goexec@latest
goexec 'http.ListenAndServe(":8080", http.FileServer(http.Dir("web")))'

# Option 4: Node.js (install http-server globally first)
npx http-server web -p 8080
```

Then open http://localhost:8080 in your browser.

**Important**: You must use an HTTP server. Opening `index.html` directly as a file (file://) will not work due to browser security restrictions on WebAssembly and CORS.

## Browser Compatibility

Verdant Thane requires a modern browser with WebAssembly support:

- **Chrome**: Version 57 or later
- **Firefox**: Version 52 or later
- **Safari**: Version 11 or later
- **Edge**: Version 16 or later

## Deployment

To deploy to a web server:

1. Build the WASM binary: `./scripts/build-wasm.sh`
2. Copy the entire `web/` directory to your web server
3. Ensure all three files are served with correct MIME types:
   - `.html` → `text/html`
   - `.js` → `application/javascript`
   - `.wasm` → `application/wasm`

Most web servers handle these automatically, but you may need to configure MIME types explicitly.

## Storage

The browser version uses `localStorage` to persist:
- High scores
- Game settings (audio volume, mute states, chat preferences)

Data is stored per-origin (domain + protocol + port) and persists across browser sessions.

## Performance

The WASM build includes all assets (images, audio, fonts) embedded in the binary, resulting in:
- Binary size: ~48MB
- Initial load time: Depends on connection speed
- Runtime performance: Target 60 FPS with 800 ships (may vary by browser and hardware)

For best performance:
- Use a recent browser version
- Close other tabs/applications to free up memory
- Ensure hardware acceleration is enabled in browser settings

## Limitations

The browser version has some limitations compared to the desktop builds:
- **No command-line flags**: All debug and performance testing flags are disabled
- **No custom configuration**: Settings are controlled through the in-game settings menu
- **Browser tab focus**: Game may pause when tab loses focus (browser-dependent behavior)

## Troubleshooting

### Game doesn't load
- Check browser console (F12) for errors
- Verify all three files (index.html, wasm_exec.js, verdant-thane.wasm) are present
- Ensure you're accessing via HTTP/HTTPS, not file://

### Performance issues
- Close other browser tabs
- Try a different browser
- Check if hardware acceleration is enabled
- Reduce browser window size (smaller canvas = better performance)

### Audio doesn't work
- Check browser audio permissions
- Verify volume settings in-game
- Some browsers block audio until user interaction - click on the page first

### Settings/scores don't persist
- Check if localStorage is enabled in browser settings
- Verify you're not in incognito/private browsing mode
- Check if browser is set to clear data on exit
